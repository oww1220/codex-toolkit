# Quota Saver

## 목적

요청한 결과와 필수 품질은 유지하면서 선택적인 조사, 도구 호출, 검증 범위와 설명을 줄인다.

## 제약

- ✅ 사용자 요구, 안전성, 데이터 손실 방지, 신뢰 경계의 검증은 줄이지 않는다.
- ✅ 다른 적용 스킬의 필수 절차와 승인 게이트는 지키되, 허용되는 가장 짧은 경로를 선택한다.
- ✅ 이미 확보한 대화와 코드 근거를 먼저 재사용한다.
- ⛔ 절약을 이유로 추측을 사실처럼 말하거나 필요한 오류 처리를 생략하지 않는다.
- ⛔ 요청하지 않은 리팩터링, 문서, 기능, 호환성 계층을 추가하지 않는다.

## 작업 방식

1. 요청 결과와 반드시 확인할 위험을 한 번 정하고, 선택적인 작업은 제외한다.
2. 관련 파일과 호출부만 검색한다. 전체 저장소 탐색은 작업 범위가 저장소 전체일 때만 한다.
3. 독립적인 조회는 한 번의 도구 호출로 묶는다. 웹 검색은 사용자가 요청했거나 최신성·정확성 규칙상 필요할 때만 한다.
4. 단일 에이전트로 진행한다. 서브에이전트는 사용자가 요청했거나 적용 중인 필수 절차가 요구할 때만 사용한다.
5. 변경에는 가장 직접적인 검증 하나를 우선 실행한다. 전체 검증은 변경 영향이 넓거나 직접 검증으로 충분하지 않을 때만 한다.
6. 요청 결과가 확인되면 탐색을 끝낸다. 막혔다면 이미 확인한 근거와 필요한 다음 입력만 짧게 보고한다.

## Superpowers와 함께 사용할 때

- brainstorming은 필요한 질문과 승인 가능한 최소 설계만 제시한다.
- TDD는 동작을 증명하는 가장 작은 실패 테스트부터 시작한다.
- verification은 완료 주장에 직접 필요한 명령을 실행한다.
- 필수 게이트 자체를 건너뛰지 않는다.

## 출력

- 중간 보고는 작업이 길어질 때만 한두 문장으로 남긴다.
- 최종 답변은 결과, 핵심 변경, 검증 또는 미검증 사항만 담는다.
- 사용자가 상세 설명이나 보고서를 요청하면 그 범위는 줄이지 않는다.

## 완료 게이트

요청한 결과, 필수 절차, 안전 조건을 충족했고 직접 관련된 검증을 실행했거나 실행하지 못한 이유를 밝혔을 때만 완료로 보고한다.
