# 주석 작업 서브에이전트 워크플로

코드 맥락 주석을 작성하기 전에는 범위와 실제 동작을 서로 다른 관점으로 조사하고, 작성 후에는 대상 전체의 누락을 독립 검증한다.

## 공통 원칙

- 사용자 지정 디렉터리·모듈·파일 전체가 대상이다. Git 변경 파일만 조사하지 않는다.
- 사전 조사자 2명과 사후 reviewer는 읽기 전용이며 파일을 수정하지 않는다.
- 각 조사자에게 대상 경로, 작업 언어의 레퍼런스, 사용자 요구사항을 명시한다.
- 복합 파일은 관련 레퍼런스를 모두 제공한다. 예를 들어 TSX는 TypeScript와 React 레퍼런스를 함께 읽는다.
- 대상 밖의 호출자·타입·설정은 근거 확인을 위해 읽을 수 있지만 주석 작성 범위를 임의로 넓히지 않는다.
- 확인되지 않은 의도는 추측하지 않고 근거 부족으로 표시한다.

## 사전 병렬 조사

주석을 작성하기 전에 아래 서브에이전트 2명을 동시에 실행한다. 두 결과를 모두 회수하기 전에는 작성하지 않는다.

### 1. 범위 조사자

대상 전체와 언어별 `필수 적용 범위`를 대조해 주석이 필요한 모든 구문 위치를 찾는다.

확인 항목:

- 선언, 계약, 매개변수, 반환, 예외
- 지역 변수, 상태, 참조, 파생값, store
- 조건 분기, 조기 반환, 반복, catch, finally
- effect, watch, 구독, cleanup, 외부 호출
- props, emits, 이벤트 handler, 템플릿 분기·반복
- 스타일 제약과 언어별 레퍼런스의 나머지 필수 항목

각 발생 지점을 다음 형식으로 보고한다.

```text
파일:위치 / 구문 / 필요한 설명 / 현재 주석 상태
```

`현재 주석 상태`는 `없음`, `부족`, `현재 구현과 불일치`, `충분` 중 하나로 기록한다. 충분한 기존 주석도 목록에 남겨 전수 확인 사실을 보여준다.

### 2. 맥락 조사자

구현, 호출자, 데이터 흐름과 부작용을 추적해 각 주석에 들어갈 실제 의미를 확인한다.

확인 항목:

- 선언의 책임과 서비스·모듈 경계
- 입력 출처, 반환값의 소비자와 호출 조건
- 상태 변경 주체, UI·저장소·외부 시스템에 미치는 영향
- 분기·반복·예외 경로가 나타내는 도메인 의미
- 호출 순서, 비동기 순서, cleanup과 복구 책임
- 보안, 개인정보, 세션, 토큰, 외부 API 제약
- 코드만으로 드러나지 않는 설계 이유와 실패 처리 의도

각 위치를 다음 형식으로 보고한다.

```text
파일:위치 / 목적·계약 / 영향·부작용 / 이유·근거 / 불확실성
```

근거는 실제 구현·호출자·타입·설정에서 확인한다. 근거가 없으면 문구를 만들어내지 않고 `확인 필요`로 표시한다.

## 메인 에이전트 통합

메인 에이전트는 두 보고서를 `파일:위치` 기준으로 합친다.

1. 범위 조사자의 전수 목록을 `파일 × 필수 적용 범위` 목록으로 사용한다.
2. 맥락 조사자의 근거로 목적·영향·이유를 작성한다.
3. 두 결과가 충돌하면 실제 코드와 호출자를 다시 확인해 결정한다.
4. `확인 필요` 항목은 추측해 채우지 않고 추가 조사하거나 사용자에게 확인한다.
5. 주석 작성 후 대상 전체와 통합 목록을 다시 대조한다.

## 사후 독립 검증

주석 작성 후 별도의 reviewer 한 명이 작업 언어 레퍼런스를 다시 읽고 사용자 지정 대상 전체를 검수한다. 사전 보고서의 결론을 정답으로 주지 않아 독립성을 유지한다.

reviewer는 다음을 확인한다.

- 필수 구문의 모든 발생 지점이 검토됐는가
- 주석이 현재 구현·호출자·데이터 흐름과 일치하는가
- 목적·영향·이유 대신 코드를 번역해 반복하지 않았는가
- 조건·반복·예외·effect·store·props·템플릿·스타일 경로가 빠지지 않았는가
- 긴 문장, 중복, 과도한 강조로 가독성이 떨어지지 않는가
- 비밀키·토큰·개인정보·내부 접속정보가 들어가지 않았는가

누락이 있으면 다음 형식으로 보고한다.

```text
파일:위치 / 누락 항목 / 필요한 설명
```

누락이 없으면 반드시 `누락 0건`이라고 보고한다. 메인 에이전트가 보완했다면 같은 reviewer가 대상 전체를 다시 검수하며, `누락 0건` 전에는 완료하지 않는다.

## 도구가 없는 경우

메인 에이전트가 한 번에 섞어 처리하지 않고 다음 세 단계를 분리해 수행한다.

1. 범위 전수 조사
2. 구현 맥락 조사와 주석 작성
3. 레퍼런스와 대상 전체의 독립 재검토
